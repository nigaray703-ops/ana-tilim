# Ana Tilim 听力增强、离线学习与云同步设计

日期：2026-07-26  
状态：用户已逐段确认  
适用范围：现有 `prototype/` 原生 HTML、CSS、JavaScript 学习原型

## 1. 目标

在不增加底部导航、不复制现有练习流程的前提下，加入两组能力：

1. 听力增强：慢速播放、循环播放、拉丁转写显示开关，以及字母和词汇听写。
2. 离线与同步：可安装的离线网页、手动下载全部真人音频、本地优先学习、Supabase 云端自动同步。

设计必须保持现有课程内容、真人音频、学习进度和手机/平板布局稳定。当前 464 个页面渲染状态和 565 个音频覆盖目标不得减少。

## 2. 已确认的产品决定

- 采用渐进式整合，不新建“听力中心”或新的底部导航。
- 听写范围为字母和词汇，暂不加入句子听写。
- 音频速度为 `1×` 和 `0.75×`。
- 循环播放持续到用户关闭循环、切换学习内容或离开当前页面。
- 拉丁转写默认显示，可在“我的 → 学习偏好”中全局关闭。
- 程序和课程文字自动离线；真人音频由用户手动下载。
- 全部真人音频当前约 15MB，共 529 个实际文件；复用关系保持不变。
- 云端使用 Supabase。
- 国外用户可使用 Google 登录；中国大陆用户可使用邮箱验证码备用登录；未登录或网络不可用时始终可使用本地模式。
- 同步完全自动化，不提供“立即同步”按钮。
- 保留手动 JSON 导出和导入，作为独立于云端的恢复通道。

## 3. 听力增强

### 3.1 共享音频控制器

现有所有真人音频按钮继续使用统一的 `playAudio` 入口，但播放行为由一个共享音频控制器管理。控制器负责：

- 当前播放对象；
- 当前速度；
- 当前循环状态；
- 内容切换时停止旧音频；
- 播放失败提示；
- 自动播放与手动播放的一致行为。

速度选择写入学习偏好并持久化。循环只属于当前会话，不写入持久化数据，避免重新进入应用后意外连续播放。

### 3.2 控件位置

在当前焦点内容的音频区域加入紧凑的 `1× / 0.75×` 分段按钮和“循环”开关。已有“听”按钮保持主要操作，不把每个列表行扩大成复杂播放器。

阅读、字母、组合、词汇和练习中的音频都使用当前速度与循环设置。进入新的内容或页面时，循环自动关闭并停止旧音频。

### 3.3 拉丁转写

学习偏好新增：

```text
显示拉丁转写：开 / 关
```

默认值为开启。关闭后，字母和词汇学习页面不显示拉丁转写。以下情况允许临时显示：

- 听写答对后的结果；
- 用户明确展开提示；
- 错题讲解需要对照时。

实现中使用统一的转写渲染辅助函数或统一 CSS 标记，不依赖逐页面的临时隐藏逻辑。

### 3.4 字母听写

现有字母听音练习顶部增加“选择 / 听写”模式切换。

听写流程：

1. 学习者播放音频。
2. 答案字母和拉丁转写保持隐藏。
3. 学习者使用现有维吾尔语键盘输入一个字母。
4. 答错只提示重新听和重试，不立即显示答案。
5. 答对后显示正确字母、拉丁转写和完成进度。

### 3.5 词汇听写

词汇单元提供“词汇听写”入口，复用同一个听写组件和现有维吾尔语键盘，不新增全局页面。

听写目标来自当前词汇组：

1. 播放当前单词真人音频。
2. 隐藏维吾尔文、拉丁转写和中文答案。
3. 学习者输入完整维吾尔语单词。
4. 答错后可以删除、重听和继续输入。
5. 答对后显示维吾尔文、拉丁转写和中文词义。

字母与词汇听写分别记录已完成目标，写入现有 `learningProgress.practice` 结构中的独立字段，不把单次答对误记为整个练习组完成。

## 4. 离线学习

### 4.1 PWA 应用外壳

新增 Web App Manifest 和 Service Worker。Service Worker 自动缓存：

- `index.html`；
- 版本化 CSS 与 JavaScript；
- 课程数据文件；
- 应用图标和必要静态资源。

版本化程序资源采用缓存优先、版本变化后更新的策略。Service Worker 注册失败或浏览器不支持时，网站仍可在线正常使用。

### 4.2 音频缓存

真人音频使用独立、版本化的 Cache Storage 缓存，不在首次访问时自动下载。

“我的 → 离线学习”新增：

- “下载全部音频（约 15MB）”；
- 已下载文件数、总文件数和百分比；
- 当前占用空间；
- “删除离线音频”。

下载清单由现有六组真人音频 manifest 生成并去重，避免重复缓存练习中复用的字母音频。中断后再次下载时跳过已缓存文件并继续。

删除离线音频只删除音频缓存，不删除程序缓存、学习进度、设置或云端数据。

### 4.3 离线状态

页面显示简短网络状态：

- 可在线同步；
- 当前离线，本地学习可继续；
- 音频未下载且当前离线。

已经缓存的音频在离线时从 Cache Storage 播放。没有缓存的音频给出明确提示，不显示“文件损坏”。

## 5. 本地备份

“我的 → 账号与数据”保留手动备份：

- 导出一个带模式版本号的 JSON 文件；
- 导入前验证结构并显示摘要；
- 用户确认后才恢复；
- 文件无效时不修改现有数据。

备份包含：

- 学习进度；
- 错题；
- 收藏；
- 每日记录；
- 学习偏好。

备份不包含音频、账号邮箱、Supabase 会话、当前页面、当前输入或其他临时 UI 状态。

## 6. Supabase 身份验证

### 6.1 登录方式

支持两种 Supabase Auth 登录入口：

- Google OAuth；
- 邮箱一次性验证码。

Google 登录面向能够正常访问 Google 的用户。邮箱验证码作为中国大陆及其他 Google 不可用环境的备用入口。两种入口共用同一套 Supabase 学习数据表和同步逻辑。

登录失败、取消登录或网络不可用时返回本地模式，不清除本地数据。

### 6.2 前端配置

前端只读取：

- Supabase Project URL；
- Supabase Publishable key。

任何 `service_role`、数据库密码、Google Client Secret 或其他服务端密钥都不得写入网页、Git 仓库或浏览器存储。

配置为空时，应用显示“本地模式”，其余学习和离线功能照常工作。

## 7. 云端数据模型与安全

建议建立一张 `learning_backups` 表：

```text
user_id            uuid primary key
schema_version      integer not null
payload             jsonb not null
client_updated_at   timestamptz not null
updated_at          timestamptz not null default now()
```

`user_id` 对应 Supabase Auth 用户。表必须启用 Row Level Security，并分别为查询、插入和更新建立 `auth.uid() = user_id` 的已登录用户策略。

前端只能使用 Publishable key。所有读写都由用户 JWT 和 RLS 限制。实现时同时提供可在 Supabase SQL Editor 执行的建表与策略脚本。

## 8. 自动同步

### 8.1 本地优先

所有学习操作先同步写入本地存储并更新时间。云端不可用不能阻止学习或导致保存失败。

### 8.2 上传

登录后，本地数据发生变化时启动短暂防抖，随后自动上传。连续操作合并成一次写入，避免每次按键都请求云端。

离线或上传失败时保留待同步状态。浏览器恢复网络或下一次打开应用时自动重试。

### 8.3 下载与合并

登录成功和应用启动时读取云端备份，与本地数据合并：

- 完成进度按目标取合集；
- 已完成字段只前进，不因旧设备回退；
- 错题按稳定标识合并、去重并保留最近记录；
- 同一天的每日完成项取合集；
- 不同日期的每日记录保留日期较新的一份；
- 收藏和学习偏好采用更新时间较新的版本。

合并后的结果先保存到本地，再自动回写云端，保证两端最终一致。

### 8.4 状态显示

“我的”页面只显示非交互式同步状态：

- 本地模式；
- 正在登录；
- 正在同步；
- 已同步及最后同步时间；
- 当前离线，等待同步；
- 同步失败，将自动重试。

不提供“立即同步”按钮。

## 9. 错误处理

- 音频播放失败：区分未缓存离线音频和真实文件错误。
- 音频下载失败：保留已下载文件和进度，可继续下载。
- Service Worker 失败：回退到普通在线网页。
- Supabase 未配置：保持本地模式。
- 身份验证失败：显示可理解的错误，不改变学习数据。
- 云端读取失败：继续使用本地数据。
- 云端写入失败：保留本地数据和待同步状态。
- 云端内容模式版本过新：停止自动覆盖，提示需要更新应用。
- 导入文件无效：不修改任何本地或云端数据。

## 10. 组件与文件边界

在保持现有原生结构的同时，将新职责分开：

- `prototype/app.js`：页面状态、渲染、现有事件入口，以及调用新服务。
- `prototype/audio-controller.js`：播放速度、循环、停止和播放状态。
- `prototype/offline-manager.js`：Service Worker 注册、音频下载进度、缓存删除和缓存状态。
- `prototype/cloud-sync.js`：Supabase 会话、自动同步、合并和同步状态。
- `prototype/backup.js`：本地 JSON 导出、验证和导入。
- `prototype/service-worker.js`：程序与音频缓存响应。
- `prototype/manifest.webmanifest`：安装信息与图标。
- `prototype/supabase-schema.sql`：建表和 RLS 策略。

新服务通过小型、明确的函数接口与 `app.js` 通信，不把网络、缓存或文件处理逻辑继续堆入页面渲染函数。

## 11. 测试与验收

### 11.1 自动化测试

先写失败测试，再实现：

- 音频速度应用到新播放对象；
- 循环开启、关闭和页面切换停止；
- 转写偏好持久化与例外提示；
- 字母听写答错不显示答案、答对后记录目标；
- 词汇听写完整输入与进度；
- 音频清单去重、断点继续和删除不影响学习数据；
- 备份导出模式、导入验证和无效文件保护；
- 本地/云端进度合并；
- 离线待同步和恢复网络重试；
- RLS SQL 包含按 `auth.uid()` 限制的策略；
- 现有课程数据、页面状态和真人音频覆盖不回退。

### 11.2 浏览器验收

使用项目现有本地地址验证：

- 390×844 手机布局；
- 952×998 平板布局；
- 字母选择与字母听写；
- 词汇听写；
- 速度切换和循环停止；
- 转写开关刷新后保持；
- PWA 注册、程序离线加载；
- 全量音频下载、继续下载和删除；
- Google 登录入口和邮箱验证码入口；
- 本地模式；
- 自动同步状态；
- 无页面报错、无控制台警告、无横向溢出。

### 11.3 完成标准

功能只有在以下条件全部满足后才算完成：

- 项目完整检查通过；
- 至少保留 464 个渲染状态和 565 个音频覆盖目标；
- 所有新增测试经历预期失败后通过；
- 手机和平板目标流程通过浏览器验证；
- 未提交或暴露任何服务端密钥；
- 未修改或删除用户已录制的真人音频文件。

## 12. 明确不在本轮范围内

- 句子听写；
- 发音评分或录音上传；
- 新的底部导航；
- 排行榜、金币或社交功能；
- 国内自建云服务、微信登录或手机号短信网关；
- 管理后台；
- 后台内容编辑器；
- 音频重新编码或替换。
