# Ana Tilim 邮箱密码注册与登录设计

日期：2026-07-29

## 目标

在保留游客学习和 Google 登录的前提下，为 Ana Tilim 增加免费的邮箱密码注册与登录。用户登录后保持会话、同步学习记录并能管理头像和名称。新注册账号从第一单元开始。

## 已确认的产品边界

- 使用 Supabase 邮箱密码认证，不开发自定义用户名认证服务。
- 注册字段为昵称、邮箱、密码和确认密码。
- 登录字段为邮箱和密码。
- 第一阶段关闭注册邮件确认，因此不依赖 SMTP。
- 第一阶段不提供邮件找回密码，并在界面明确提醒用户保存密码。
- Google 登录和游客学习继续保留。
- 登录成功和注册成功后自动进入首页。
- 新注册账号使用空白云端进度，并从字母课程的第一单元开始。
- 注册前的游客进度先在本机单独备份，再重置为新账号进度，避免直接丢失。
- 已存在的账号登录时继续合并本机与云端学习记录，不执行新用户重置。
- 登录会话由 Supabase 客户端持久保存，刷新页面或重新打开浏览器后保持登录。

## 界面

登录卡片包含两个标签：

1. 登录
   - 邮箱
   - 密码
   - 登录按钮
2. 注册
   - 昵称
   - 邮箱
   - 密码
   - 确认密码
   - 注册并开始学习按钮

卡片底部继续显示 Google 登录和游客学习入口。注册区域显示“当前暂不支持邮件找回密码，请保存好密码”的提示。

## 数据与流程

### 注册

1. 前端校验昵称、邮箱和密码。
2. 密码至少 8 个字符，两次输入必须一致。
3. 将当前游客学习快照保存到独立的本机备份键。
4. 调用 Supabase `signUp`，并把昵称写入用户元数据。
5. 注册成功且获得会话后，初始化空白学习进度。
6. 将页面导航到首页，第一学习位置设为字母课程第一单元。
7. 空白进度随后同步到新用户的云端记录。

如果注册失败，不重置当前游客进度，也不覆盖游客备份。

### 登录

1. 调用 Supabase `signInWithPassword`。
2. 登录成功后使用现有合并逻辑同步本机与云端进度。
3. 自动进入首页。

### 保持登录

继续使用 Supabase 浏览器客户端的默认持久会话。页面初始化时恢复已有会话，并维持现有云端同步。

## 错误处理

- 无效邮箱、短密码、密码不一致在调用云端前提示。
- 邮箱已注册、密码错误等云端错误转换为简明中文提示。
- 注册失败时保留当前游客状态。
- 网络中断时不清除本机学习记录，并沿用现有自动重试机制。
- 如果 Supabase 项目仍要求邮箱确认，界面提示需要检查项目认证配置，不伪装成注册成功。

## 安全

- 不在源码中保存密码、服务端密钥或用户令牌。
- 只使用现有 Supabase 项目 URL 和公开密钥。
- 密码由 Supabase Auth 处理，应用不自行存储密码。
- 头像写入继续限制在用户自己的 Storage 文件夹。

## 测试与验收

- 注册调用包含邮箱、密码和昵称。
- 登录调用使用邮箱和密码。
- 注册失败不重置游客进度。
- 注册成功备份游客进度，并初始化第一单元的空白学习状态。
- 登录与注册成功均跳转首页。
- 刷新后已登录会话仍可恢复。
- 游客、Google 登录、邮箱验证码和现有云端同步没有回归。
- 全部自动化测试和项目检查通过。
- 本地浏览器检查登录/注册切换、桌面布局、控制台错误和关键交互。
- 部署后检查线上页面身份、注册界面和新账号起步流程。

## 不在本轮范围

- 邮件验证码和找回密码的正式 SMTP 配置。
- 手机验证码、Apple 登录和微信登录。
- 自定义用户名登录。
- 管理员人工重置密码。
