# 音频接入规则

## 音频文件放在哪里

当前项目只保留真人音频。文件统一放在：

```text
prototype/assets/audio/human/
```

按用途分成三个实际音频目录：

```text
prototype/assets/audio/human/alphabet/
prototype/assets/audio/human/combos/
prototype/assets/audio/human/vocab/
```

第四单元练习不保留重复音频文件，直接复用第一单元字母音频。对应说明在：

```text
prototype/assets/audio/human/practice/manifest.json
```

页面里引用时使用相对路径：

```text
./assets/audio/human/alphabet/human_letter_01_b.webm
```

## 文件命名规则

只使用：

- 英文小写
- 数字
- 下划线
- `.webm`

当前前缀：

| 类型 | 前缀 | 示例 |
| --- | --- | --- |
| 字母 | `human_letter_` | `human_letter_01_b.webm` |
| 组合 | `human_combo_` | `human_combo_ba.webm` |
| 词形 / 短语 / 数字 | `human_vocab_` | `human_vocab_rahmat.webm` |

不要在文件名里使用空格、中文或维吾尔文。

## 接入清单

每个音频目录都有自己的 `manifest.json`：

```text
prototype/assets/audio/human/alphabet/manifest.json
prototype/assets/audio/human/combos/manifest.json
prototype/assets/audio/human/vocab/manifest.json
prototype/assets/audio/human/practice/manifest.json
```

清单里的关键字段：

```json
{
  "file": "human_vocab_rahmat.webm",
  "outputPath": "./assets/audio/human/vocab/human_vocab_rahmat.webm",
  "reviewStatus": "已接入",
  "playable": true,
  "statusLabel": "真人音频"
}
```

## 接入前检查

每个音频接入前必须确认：

- 文本已经审校，或明确标记为仍需审校。
- 文件名和清单一致。
- 文件能在浏览器播放。
- 音量不过低或过高。
- 一个学习项只保留一个主音频。
- 如果有慢速版，另设清晰的文件名和清单字段。

## 页面播放规则

- 用户点击按钮才播放，不自动播放。
- 播放失败时显示“音频暂不可用”。
- 没有可用音频时显示“音频待录”。
- 已接入文件统一显示 `真人音频`。
- 审听发现问题时，把状态改为 `需重新录制`。

## 审校和音频的关系

推荐顺序：

1. 先审校文字。
2. 审听现有真人音频。
3. 把可用文件保持为 `真人音频已接入`。
4. 把有问题的文件标记为 `需重新录制`。
5. 重录后替换 `prototype/assets/audio/human/` 里的对应文件。
6. 更新 manifest 和测试。

不要先扩充新词，再回头补审校和音频。
