# 音频接入规则

## 音频文件放在哪里

未来录好的音频统一放在：

```text
prototype/assets/audio/
```

页面里引用时使用相对路径：

```text
./assets/audio/letter_03_b.mp3
```

## 当前状态

目前没有真实音频文件。

当前第四单元里的音频按钮只是占位，状态是：

```text
真人音频待录制
```

不要在没有音频文件时把按钮写成“已播放真实音频”。

## 文件命名规则

只使用：

- 英文小写
- 数字
- 下划线
- `.mp3`

推荐前缀：

| 类型 | 前缀 | 示例 |
| --- | --- | --- |
| 字母 | `letter_` | `letter_03_b.mp3` |
| 组合 | `combo_` | `combo_ba.mp3` |
| 词形 | `word_` | `word_rahmat.mp3` |
| 短语 | `phrase_` | `phrase_assalamu_alaykum.mp3` |
| 数字 | `number_` | `number_bir.mp3` |

## 接入数据字段

后续在 `prototype/app.js` 的字母、组合、词条或练习项里，可以加入这些字段：

```js
{
  value: "رەھمەت",
  latin: "rehmet",
  audioFile: "./assets/audio/word_rahmat.mp3",
  audioStatus: "真人音频已接入",
  audioReviewStatus: "已审校",
  audioSpeaker: "speaker_01"
}
```

当前没有真实音频时，保持：

```js
{
  audioFile: "",
  audioStatus: "真人音频待录制",
  audioReviewStatus: "待母语者审校"
}
```

## 可选音频清单文件

正式接入时可以新建：

```text
prototype/assets/audio/manifest.json
```

建议结构：

```json
[
  {
    "id": "word_rahmat",
    "text": "رەھمەت",
    "latin": "rehmet",
    "file": "./assets/audio/word_rahmat.mp3",
    "unit": "第三单元",
    "kind": "word",
    "reviewStatus": "已审校",
    "speaker": "speaker_01"
  }
]
```

## 接入前检查

每个音频接入前必须确认：

- 文本已经审校
- 文件名和清单一致
- 文件能在浏览器播放
- 音量不过低或过高
- 同一项目只有一个主音频
- 如果有慢速版，文件名加 `_slow`

## 页面播放规则

建议后续播放逻辑：

- 用户点击按钮才播放，不自动播放。
- 播放失败时显示“音频暂不可用”。
- 没有 `audioFile` 时显示“真人音频待录制”。
- 不要阻止用户继续学习，因为音频可能晚于课程内容接入。

## 审校和音频的关系

推荐顺序：

1. 先审校文字。
2. 再确定录音清单。
3. 再录音。
4. 再接入项目。
5. 最后做听音和跟读测试。

不要先录音再改词形。
